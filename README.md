# OpenPaths

OpenPaths is a final-year project that explores road reallocation for active mobility in Malta. The project builds a multimodal road graph from OpenStreetMap data, estimates bicycle comfort and car routing costs, generates origin-destination demand, and compares heuristic strategies for converting car road space into protected cycling infrastructure.

The main workflow is currently research-notebook driven through [`Code/main.ipynb`](Code/main.ipynb). The reusable logic is split into Python modules for preprocessing, demand generation, optimisation, plotting, and SUMO simulation.

## What The Project Does

- Downloads and prepares Malta road networks with OSMnx.
- Combines drive and bike networks into a single multimodal `networkx.MultiDiGraph`.
- Enriches edges with elevation, grade, safety class, bike cost, car cost, locality, region, and reallocatability attributes.
- Generates synthetic OD demand using population-weighted residential sampling, destination POIs, regional trip shares, and a gravity-style distance decay model.
- Calibrates OD demand against a target average trip distance.
- Runs lane/segment reallocation heuristics, including random, edge betweenness, OD betweenness, and component-connection approaches.
- Evaluates proposed networks using OD cost, directness, connectedness, coverage, protected-network reachability, and car harm metrics.
- Projects optimised simplified graphs back onto an unsimplified SUMO-facing network.
- Exports SUMO OSM, TAZ, OD matrix, route, and simulation files.
- Plots network attributes, OD flows, optimisation progress, proposed cycling networks, and SUMO outputs.

## Requirements

- Python 3.12 was used for the current environment.
- A Python environment with the packages in [`requirements.txt`](requirements.txt).
- SUMO, if you want to build and run traffic simulations.

SUMO commands such as `netconvert`, `od2trips`, `duarouter`, and `sumo` must be available on your `PATH`. [`Code/Demand/sumoRun.py`](Code/Demand/sumoRun.py) also references `C:\Program Files (x86)\Eclipse\Sumo\tools\edgesInDistricts.py`, so update that path if SUMO is installed elsewhere.

## Optimisation Outputs

The optimiser returns:

- an updated `MultiDiGraph` containing the proposed reallocations;
- a pandas `DataFrame` with per-iteration evaluation metrics.

Common generated files include:

```text
Code/Output/ProposedGraphs/
|-- optimised_graph_results_df.csv
|-- <heuristic>_graph.pkl
`-- <heuristic>_diff_log.json
```

The `diff_log` files record reallocation events and are used to transfer simplified-graph changes onto the unsimplified SUMO network.

## SUMO Notes

SUMO scenarios are written to [`Simulations/`](Simulations/). The current workflow uses:

- `types.add.xml` for car and bicycle vehicle definitions;
- `localities.poly.xml` for TAZ polygons;
- `od_matrix.xml` for region/locality demand;
- `templates/Scenario.sumocfg` as the reusable SUMO configuration template;
- `templates/meandata.add.xml` as the reusable edge-data output configuration;
- one scenario directory per baseline or heuristic network.

Each scenario directory contains the generated files needed to run that simulation instance, including `<scenario>.sumocfg`, `<scenario>.net.xml`, the generated car and bicycle route files, `meandata.add.xml`, and `vtypes_tmp.xml`. The `.sumocfg` file is created from `templates/Scenario.sumocfg` by replacing `{scenario}` with the scenario name, while `meandata.add.xml` is copied from `templates/`. The `.sumocfg` file should be run from inside its scenario directory because it uses relative paths to the scenario files and the shared `../types.add.xml` file.

The baseline scenario is named `Malta_island`; heuristic scenarios include names such as `edge_betweenness`, `OD_betweenness`, `L2C`, and `Random`.
